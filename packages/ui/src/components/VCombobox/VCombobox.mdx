# Combobox

Champ de recherche avec liste de suggestions et sélection simple ou multiple — le
pattern ARIA **combobox/listbox** qu'aucune primitive native ne couvre (`<datalist>`
n'est ni stylable ni multiple). Le composant est **assemblé à partir des briques du
DS** :

- **`VInput`** pour le champ de recherche (`role="combobox"`) ;
- **`VPopover`** pour la liste, qui porte elle-même `role="listbox"` (top layer, ancrée en
  pur CSS sur le contrôle) ;
- **`VChip`** pour les valeurs sélectionnées en mode multiple.

Le focus DOM reste dans l'input pendant la navigation (`aria-activedescendant`) ;
l'ouverture est pilotée par l'état interne, la fermeture par le light dismiss maison
(`focusout`).

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { VCombobox, type ComboboxOption } from '@vectis/ui'

const pays: ComboboxOption[] = [
  { value: 'fr', label: 'France' },
  { value: 'be', label: 'Belgique' },
  { value: 'sn', label: 'Sénégal' },
]
const value = ref('')
</script>

<template>
  <VCombobox v-model="value" :options="pays" placeholder="Choisir un pays…" aria-label="Pays" />
</template>
```

## Options

Chaque option est un `ComboboxOption` — `{ value, label, disabled? }`. Le `label` est
affiché et filtré, la `value` alimente le `v-model` ; une option `disabled` est
présentée mais ni sélectionnable ni atteignable au clavier.

Le filtrage est **insensible à la casse et aux accents** (normalisation NFD) : taper
`sene` propose `Sénégal`.

## Groupes et séparateurs

Une entrée d'`options` n'est pas forcément une option : ce peut être un **groupe
nommé** — `{ label, options }`, rendu en `role="group"` avec un micro-libellé — ou un
**séparateur** — `{ separator: true }`, un filet pleine largeur. Les trois formes se
mélangent librement dans le même tableau, dans l'ordre voulu.

Le micro-libellé d'un groupe occupe la hauteur d'une option, texte centré verticalement : le
rythme vertical de la liste reste le même de bout en bout, quelle que soit la taille du champ
et en densité compacte.

```ts
const pays: ComboboxItem[] = [
  { label: 'Europe', options: [{ value: 'fr', label: 'France' }] },
  { separator: true },
  { label: 'Afrique', options: [{ value: 'sn', label: 'Sénégal' }] },
  { value: 'other', label: 'Autre / non listé' }, // option nue : toujours valide
]
```

Groupes et séparateurs sont **du rendu, rien d'autre** : la navigation clavier parcourt
la liste **à plat** et ne s'arrête jamais sur un libellé de groupe ni sur un filet. Au
filtrage, un groupe dont plus aucune option ne correspond **disparaît, libellé compris**,
et les séparateurs devenus orphelins (en tête, en fin, ou deux d'affilée) ne sont pas
rendus — la liste filtrée ne laisse donc jamais de filet flottant.

## Recherche

Le filtre ne s'active **qu'à la frappe**. Un `v-model` déjà renseigné affiche son
libellé sans restreindre la liste : à la réouverture, **toutes** les options sont
reproposées (l'option courante reçoit une coche), et ce n'est qu'en tapant que la
liste se réduit. **Entrée** sélectionne l'option active — ou l'unique résultat quand
il n'en reste qu'un.

Un **chevron** à droite indique l'état et pivote à l'ouverture. Une **croix**
(`clearable`, activée par défaut — la prop `clearable` de `VInput`, rendue à gauche
du chevron) apparaît dès qu'il y a **quelque chose à effacer** (une valeur, des Chips
ou une recherche) et vide **toute la sélection**.

## Recherche serveur

Par défaut le filtrage est **local**. Avec une source distante, la liste arrive déjà
filtrée : passer `:filter="false"` — sinon le filtre local rejouerait sur `label` et
écarterait silencieusement les résultats appariés sur un autre champ. `filter` accepte
aussi un **prédicat** `(option, query) => boolean` pour une correspondance
personnalisée (le prédicat reçoit la requête brute trimée, pas sa forme normalisée).

L'événement **`search`** porte le terme saisi. Il est **débouncé** (`search-debounce`,
250 ms par défaut ; `0` = synchrone) sauf à l'ouverture du panneau, où il part
immédiatement pour permettre un premier chargement. Un même terme n'est **pas réémis** :
rouvrir le panneau ne relance pas la requête. Aucune requête ne part sur un panneau
fermé, y compris pour une frappe dont le délai n'était pas écoulé.

Le composant n'annule pas les requêtes en vol : c'est au consommateur d'ignorer les
réponses obsolètes (jeton d'appel, `AbortController`…).

Les **libellés des valeurs sélectionnées sont mémorisés** : une valeur choisie garde
son libellé (VChip, texte du champ) même quand la recherche suivante la fait disparaître
des options. Une valeur qui n'a jamais figuré dans aucune page reste affichée telle
quelle — pour l'éviter sur un formulaire d'édition, inclure l'option correspondante
dans le premier `options` rendu.

## Chargement et pagination

`loading` couvre les deux moments : sans option affichée, le panneau montre l'état de
chargement (jamais « aucun résultat », qui dirait l'inverse de la réalité) ; avec des
options déjà affichées, un spinner apparaît en pied de liste. Dans les deux cas, le
chevron du champ laisse sa place à un spinner, au même endroit et sans saut de largeur.
`loading-text` personnalise le message, les slots `#loading` et `#empty` (qui reçoit
`query`) remplacent entièrement ces contenus — pour proposer une action « créer… », par
exemple.

`has-more` rend une sentinelle en pied de panneau : son entrée dans la vue émet
**`load-more`**. La détection tient compte du chargement en cours et relance
l'évaluation à chaque page reçue, de sorte qu'une page trop courte pour remplir le
panneau n'interrompt pas la pagination.

## Icône d'option

Le champ **`icon`** d'une option affiche une icône avant son libellé — un nom Material
d'icône, ou un rendu explicite (`{ src }`). Elle est rendue à l'emplacement prévu par la
rangée, donc alignée et espacée comme le reste du contenu.

C'est la voie à préférer pour une simple icône, plutôt que le slot `#option` : ce dernier
est rendu **à l'intérieur** du libellé, une icône qu'on y placerait n'atteindrait pas
l'emplacement de début ni sa gouttière. La fin de la rangée, elle, est réservée à la coche
de sélection.

## Personnaliser une option

Le slot **`#option`** remplace le contenu d'une option et reçoit `{ option, index,
active, selected }`. La coche de sélection reste gérée par le composant.

## Sélection multiple

Avec `multiple`, le `v-model` devient un `string[]` et chaque valeur s'affiche en
`VChip` retirable. Le panneau reste ouvert après un choix (on enchaîne les
sélections) ; **Retour arrière** sur un champ de recherche vide retire la dernière
valeur. Hors focus, le champ de saisie se replie pour ne laisser que les Chips, sans
espace vide.

<Canvas of={VComboboxStories.SelectionMultiple} />

### Personnaliser les Chips

Le slot **`#chip`** remplace le VChip d'une valeur sélectionnée. Il reçoit :

- `value` et `label` — la valeur et son libellé résolu ;
- `option` — l'option complète (donc son `icon`), ou `undefined` si cette valeur n'a jamais
  été vue dans `options`. Le composant mémorise les options sélectionnées : en source
  asynchrone, une valeur choisie disparaît des résultats suivants sans perdre son libellé
  ni son icône ;
- `remove` — à câbler sur l'action de retrait, sans quoi la valeur ne serait plus retirable ;
- `size` et `compact` — le gabarit calculé pour tenir dans le champ. Les reprendre sur le
  VChip personnalisé évite de faire grandir le champ.

## Tailles

`size` accepte `sm` (32 px), `md` (40 px, défaut — aligné sur `VInput`) et `lg` (48 px),
combinable avec `compact` (-4 px). En multiple, les Chips restent **un cran sous le champ**
pour tenir dedans sans le faire grandir : `xs` (24 px) jusqu'à `md`, `sm` (32 px) en `lg`.
Sous le cran le plus bas de chaque paire, le rattrapage passe par `compact` plutôt que par
une taille de moins — `size="sm"` donne des Chips `xs` compact (20 px), `size="lg"` +
`compact` des Chips `sm` compact (28 px). Le panneau d'options suit la taille du champ :
rangées de 32/40/48 px, et en `lg` la même typographie (16 px) et les mêmes icônes (24 px)
que le champ — le libellé d'une option ne change pas de taille en passant dans le champ.

## États

`invalid` force l'état d'erreur (bordure rouge, pour la validation serveur) ;
`disabled` grise le champ (nuances par tokens, sans opacité). `placeholder` et
`empty-text` (message quand aucune option ne correspond) sont personnalisables.

## Accessibilité

- Contrat ARIA combobox/listbox : `role="combobox"` + `aria-expanded` /
  `aria-controls` / `aria-autocomplete="list"` sur l'input, `role="listbox"` sur le
  panneau, `role="option"` + `aria-selected` par option.
- **Le focus reste dans l'input** ; l'option courante est signalée par
  `aria-activedescendant` (jamais de focus déplacé sur les options).
- Clavier : Flèches haut/bas (avec bouclage, les options désactivées sont sautées),
  Entrée sélectionne, Échap ferme, Tab ferme et poursuit la tabulation, Retour arrière
  retire la dernière valeur en multiple.
- Nommer le champ via `aria-label` (ou un `label` associé) — l'attribut est reporté
  sur l'input interne.
- Un groupe est un `role="group"` nommé par `aria-labelledby` (l'équivalent d'un
  `<optgroup>`), enfant autorisé du `role="listbox"` ; son libellé n'est ni focusable ni
  sélectionnable. Le séparateur est en revanche **décoratif** (`role="presentation"`) : le
  regroupement est déjà porté par les groupes et leurs noms, un `role="separator"` ne
  serait pas un enfant valide d'une listbox.
- Le spinner du **champ** est décoratif (`aria-hidden`) : l'annonce du chargement vient
  du `role="status"` inséré dans le panneau, une seule fois.

Les libellés accessibles de ce composant viennent du dictionnaire du design system : ils se traduisent globalement (voir **Fondations › Internationalisation**), et les props texte restent prioritaires pour un ajustement au cas par cas.

## Support navigateur

Le panneau s'appuie sur la **Popover API** et le **CSS Anchor Positioning** (largeur
alignée sur le contrôle via `anchor-size(width)`, ancre confinée par `anchor-scope`)
**sans fallback** — décision du projet : Chrome/Edge 125+, Safari 26+, Firefox non
supporté tant que l'anchor positioning n'y est pas stable.
