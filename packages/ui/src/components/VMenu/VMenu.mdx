# Menu

A dropdown action menu (the ARIA menu pattern) built on the **Popover API** and **CSS Anchor
Positioning**: the trigger invokes the panel through `popovertarget` (implicit anchor, native
light dismiss, top layer with no z-index), with no external dependency. The JavaScript is
limited to the roving focus, the keyboard navigation and the submenu orchestration.

The trigger is supplied by a scoped slot — set `triggerProps` as they come:

```vue
<VMenu>
  <template #trigger="{ triggerProps }">
    <VButton v-bind="triggerProps">Actions</VButton>
  </template>
  <VMenuItem label="Rename" icon-start="edit" @select="rename" />
  <VMenuSeparator />
  <VMenuItem label="Delete" icon-start="delete" danger @select="remove" />
</VMenu>
```

## Items

`VMenuItem`: `label` + `sublabel` (a secondary description), `icon-start` / `icon-end` (an icon
name or an explicit render `{ src }` / `{ component }`), and the `#default` / `#sublabel` /
`#start` / `#end` slots, which win. Selecting an item emits `select` and **closes the menu**
(focus handed back to the trigger).

> The icons the design system renders itself are embedded SVGs: no font is required. Your own
> icon names, on the other hand, come from the font or the library you wire in (see the README).

## Groups and separators

`VMenuGroup` (`role="group"` named through `aria-labelledby`, the label not focusable) structures
long lists; `VMenuSeparator` renders a `VSeparator` (an `<hr>`, implicit role). The roving focus crosses the
groups, and the labels are skipped.

A section header occupies the height of a row, its text vertically centred: the list's vertical
rhythm stays the same from end to end, whatever the menu size and in compact density too.

<Canvas of={VMenuStories.Groups} />

## Navigation items

`href` renders the item as an `<a role="menuitem">` — a real link (openable in a new tab,
`target`/`rel` attributes through fallthrough). A `disabled` link becomes inert (`href` removed,
`aria-disabled="true"`) and the roving focus skips it.

## Submenus

A `VMenuItem`'s `#submenu` slot renders a **recursive** nested panel: the item becomes the
invoker of the subpanel (a chevron replaces `icon-end`; `href` and `select` are ignored). The
native popover stack handles the light dismiss and the cascading close — opening a branch closes
its sibling.

Opening: click, ArrowRight / Enter / Space (focusing the first subitem), or hover after a
**150 ms intent delay**. ArrowLeft and Escape each close **one level** at a time (focus handed
back to the parent item); on the root panel, Escape closes the menu.

On hover, the hovered item takes the focus (hover and roving focus stay synchronized: a single
highlight at a time); the parent item of an open submenu keeps its background through
`aria-expanded`:

## Sizes

Three panel sizes (`sm` — the default — items 32px min, `md` 40px min, `lg` 48px min); `compact`
removes 4px. The items are not sized separately: the panel carries the shared `v-control` class
and the items consume the design system's common table — height, indent, icon/label gap,
typography and icons. `sm` and `md` share their typography (14px), icons (20px) and gap (8px);
`lg` moves to 16px, 24px and 12px — so a menu opened from an `lg` button is at its scale. The
size is set on the **root** panel and inherited by every submenu.

## Width

By default the panel takes the width of its content, bounded by tokens (a minimum and a maximum —
the ceiling always stays below the viewport). The `width` prop sets it explicitly: any CSS length
or keyword (`16rem`, `max-content` to match the widest item). It applies to the **root** panel
only: submenus keep the default width. A width narrower than the content truncates the labels.

`matchTrigger` takes the problem from the other end: it replaces the minimum width with the
**trigger's**, so the panel can never look shrunken under the button that opens it, while staying
free to widen for its content (this is the setting of VDataTable's "rows per page" menu). The two
props combine — the trigger floor then wins over `width`. A trigger wider than the maximum width
deliberately overflows that ceiling: the alignment request takes precedence. The floor is measured
in CSS on the panel's anchor, without a line of JavaScript; like the rest of the anchoring, it
assumes a browser that implements anchor positioning.

## Placement

`placement` (`bottom-start` by default, `bottom`, `bottom-end`, `top-start`, `top`, `top-end`)
rests on `position-area` with automatic flipping (`position-try-fallbacks`) when room runs out.
Submenus open in `right-start`. Labels are bounded by the panel's maximum width:

## Accessibility

- ARIA roles: `role="menu"` on the panel, `role="menuitem"` per item (button or link),
  `aria-haspopup`/`aria-expanded` on the trigger and on the items carrying a submenu.
- **Opening singles out a command only when it was asked for from the keyboard.** Opened with
  Enter or Space, the menu takes the first item, ready to be chosen. Opened with a mouse or a
  finger, the focus stops at the panel and no row is highlighted — the reader has not asked for
  a choice yet. Either way the keyboard works from the very next keystroke: the arrows enter the
  list from the panel, Down from the top and Up from the bottom.
- **Roving focus**: no item is in the tab order, the focus being moved from item to item by the
  arrows; Up/Down with wrap-around, disabled items skipped.
- Keyboard: Enter/Space selects, Escape and ArrowLeft go up one level, Tab closes the whole menu.
  Closing hands the focus back to the trigger.
- Native light dismiss (a click outside the menu, a loss of focus) through the Popover API.
- Hover moves the focus to the hovered item, so there is never more than one highlight; closing a
  submenu on pointerleave is refused while the focus is inside it, so a stray pointer cannot cut
  off a keyboard user.
- The opening animations respect `prefers-reduced-motion`.

## Browser support

Popover API + CSS Anchor Positioning **with no fallback** (a project decision): Chrome/Edge 125+,
Safari 26+, Firefox 147+. Programmatic submenu
openings (keyboard, hover) use `showPopover({ source })`, which raises the effective floor to
Chrome/Edge 129+.
