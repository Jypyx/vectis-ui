# Switch

Switch built on the native `<input type="checkbox" role="switch">` — correct on/off semantics for
screen readers, with keyboard and forms for free. The track/thumb rendering is pure CSS driven by
`:checked`; the JavaScript is limited to the v-model bridge and the refusal `readonly` asks
for. The input sits inside a `<label>`, so clicking the label toggles the switch with no
`for`/`id`; the root is a layout box around that label and the optional hint.

A single size: a 40×20px track (the `--vectis-control-size-switch-w/h` tokens), aligned on the
height of VCheckbox/VRadio, with the thumb inset by `--vectis-control-size-switch-pad`.

## Label position

`label-position` places the label after (`end`, the default) or before (`start`) the switch.

<Canvas of={VSwitchStories.LabelPosition} />

## Label and hint

`label` is the text beside the switch, and the default slot replaces it when the label needs
more than text. `hint` draws a caption underneath, tied to the input through
`aria-describedby`: a consumer's own `aria-describedby` is kept and the hint appended to it. The
hint is rendered outside the `<label>`, since everything inside a label becomes the accessible
name, and it lines up with the text on either side (`label-position`, `spread`).

<Canvas of={VSwitchStories.WithHint} />

## Spread

`spread` makes the root take the full width: label and switch are pushed to the container's
opposite ends. It combines with `label-position` to choose which side the switch goes to.

<Canvas of={VSwitchStories.Spread} />

## States

`disabled` switches the control to greys: the track becomes
`--vectis-color-surface-muted` (checked or not) and the thumb `--vectis-color-text-subtle` with no
shadow — the colour of VCheckbox/VRadio's disabled tick and dot, visible in both themes. No
opacity trick.

<Canvas of={VSwitchStories.Disabled} />

`invalid` rings the track in `--vectis-color-danger` and sets `aria-invalid` on the input, the
same pair of selectors VCheckbox and VRadio use — so a required switch reports both the rule the
browser checked and one only you can. It is drawn as a ring rather than as a border colour: the
track has no border to tint, and a shadow changes no geometry where a border would eat into the
padding the thumb travels in.

## Read-only

`readonly` shows the setting without letting it change. The component cancels the click, which
also covers Space and a click on the label. The switch stays focusable, is submitted with its form
and carries `aria-readonly`. Both positions say so on screen: an ON switch trades the accent for
`--vectis-color-text-muted`, an OFF one sinks to `--vectis-color-surface-sunken` behind a hairline
ring, the pair a read-only VCheckbox takes for its box.

A read-only switch still takes part in constraint validation, unlike a natively read-only
field: `readonly` with `required` and the switch off leaves a form the reader cannot submit and
cannot fix. Validate the model yourself in that case.

## Forms

The native attributes (`name`, `value`, `required`, `aria-*`…) pass through by fallthrough onto
the input, not onto the wrapper: the switch takes part in forms normally.

## Accessibility

- `role="switch"`: screen readers announce "on/off" rather than "checked/unchecked".
- The input is hidden with `opacity: 0` (never `display: none`): it stays focusable by keyboard
  (Space toggles it) and submitted with the form.
- Visible focus through a ring (`--vectis-focus-ring-*`) on the track, never removed.
- In Windows forced colors the track draws its own edge and an ON switch takes the system
  `Highlight` pair. A switch is nothing but backgrounds and a shadow, all of which that mode
  flattens, so without those rules it loses its state and its outline at once.
- The thumb's transition respects `prefers-reduced-motion`.
