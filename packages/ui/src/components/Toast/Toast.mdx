# Toast

Notifications déclenchées **par programme** : monter `<Toaster />` une fois (racine de
l'app), puis appeler `toast(options)` depuis n'importe où — composant, store, retour d'API
asynchrone. La file est un état réactif au niveau module (pas de provide/inject) ; elle est
**client-only** : ne jamais appeler `toast()` pendant le rendu SSR.

```vue
<!-- App.vue -->
<Toaster placement="bottom-right" :duration="5000" />
```

```ts
import { toast, dismissToast } from '@vectis/ui'

async function save() {
  try {
    await api.save()
    toast({ tone: 'success', message: 'Modifications enregistrées.' })
  } catch {
    toast({ tone: 'danger', title: 'Erreur', message: 'Le serveur ne répond pas.', duration: 0 })
  }
}
```

L'affichage passe par la Popover API : un `popover="manual"` **par placement** porte la
pile (top-layer natif, aucun z-index), l'empilement est du pur CSS — le JavaScript se
limite au pont file → `showPopover()`/`hidePopover()` et aux timers d'auto-fermeture.

## Tones

Cinq tones × deux variants. `tonal` (défaut) : fond `-surface`, bordure `-border`, icône et
titre teintés. Le tone `neutral` s'appuie sur `surface-overlay`.

<Canvas of={ToasterStories.Tones} />

`solid` : couleur pleine du tone. `warning` utilise `--ds-color-text-on-warning` (texte
sombre, le blanc échoue AA sur amber) ; `neutral` passe en contraste inversé
(`surface-inverse`, style tooltip), lisible dans les deux thèmes.

<Canvas of={ToasterStories.Solid} />

## Placements

Six positions d'écran, en piles indépendantes. La prop `placement` du Toaster fixe le
défaut ; l'option `placement` d'un toast le surcharge. Coordonnées **physiques**
(`top/left`…) : une notification est une position d'écran, indépendante de la direction de
lecture — comme les notifications de l'OS.

<Canvas of={ToasterStories.Placements} />

## Durée d'affichage

`duration` (prop du Toaster : défaut 5000 ms, surchargeable par toast) pilote la fermeture
automatique. Survoler une pile **suspend ses timers** ; ils repartent à la durée pleine au
départ du pointeur (WCAG 2.2.1).

<Canvas of={ToasterStories.AutoFermeture} />

`duration: 0` rend le toast persistant : il reste affiché jusqu'à fermeture par la croix
(IconButton `close`, masquable via `closable: false`) ou par `dismissToast(id)`.

## Icônes

Chaque tone a son icône Material Symbols par défaut : `notifications` (neutral), `info`
(accent), `check_circle` (success), `error` (danger), `warning` (warning). L'option `icon`
accepte tout nom d'icône ou un rendu explicite (`{ src }`, comme partout ailleurs) ;
`icon: false` la retire. Les icônes de tone sont des SVG embarqués : elles s'affichent sans
aucune police (voir Icon).

<Canvas of={ToasterStories.IconePersonnalisee} />

## Largeur

Largeur par défaut : token `--ds-control-size-toast-width` (22rem). L'option `width`
(longueur CSS) la remplace par toast — toujours bornée à `100vw − marges`, un toast ne
déborde jamais du viewport.

<Canvas of={ToasterStories.Largeur} />

## Empilement

Les toasts d'un même placement s'empilent, le plus récent près du bord de l'écran (pur
CSS `column`/`column-reverse`, la file reste append-only). L'entrée glisse depuis le bord
via `@starting-style` ; la sortie individuelle n'est pas animée (choix de simplicité), la
pile qui se vide fait un fondu.

## Accessibilité

- Rôle par toast : `role="alert"` (interruptif) pour `danger`/`warning`, `role="status"`
  (poli) sinon — l'annonce du premier toast poli d'une pile peut être manquée par certains
  lecteurs d'écran (la live region naît avec son contenu) ; les `alert` sont annoncés à
  l'insertion.
- Chaque pile est un landmark `role="region"` nommé par la prop `label`
  (« Notifications ») ; la croix reçoit `closeLabel` (« Fermer »).
- Le focus n'est jamais volé : un toast s'affiche sans interrompre la saisie en cours.
- Pause des timers au survol ; les animations respectent `prefers-reduced-motion`.

Les libellés accessibles de ce composant viennent du dictionnaire du design system : ils se traduisent globalement (voir **Fondations › Internationalisation**), et les props texte restent prioritaires pour un ajustement au cas par cas.
