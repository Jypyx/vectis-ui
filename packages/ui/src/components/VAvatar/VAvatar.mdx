# Avatar

Représentation ronde d'une personne (ou entité) avec une **cascade de contenu** : image →
icône → initiales (dérivées du nom) → slot de repli. La taille suit l'échelle unifiée des
contrôles (`xs`/`sm`/`md`/`lg`/`xl`, comme `VButton`), la couleur est dérivée automatiquement
du nom ou fournie par le consommateur, et l'avatar peut devenir **cliquable** (lien ou bouton)
au besoin.

## Tailles

Échelle partagée `xs`/`sm`/`md`/`lg`/`xl` (24 → 56px) via la classe `v-control` — la même
que `VButton`, `VInput`, etc. Le disque est carré (`--control-height`), les initiales suivent
la typo tokenisée du contrôle (`--control-font-size`).

<Canvas of={VAvatarStories.Tailles} />

## Compact

`compact` retranche 4px à la hauteur à chaque taille (typo et icône inchangées) — cohérent
avec les autres contrôles.

<Canvas of={VAvatarStories.Compact} />

## Contenu : image, icône, initiales

La source affichée suit une priorité stricte :

1. **`src`** — l'image. Si son chargement échoue (`error`), l'avatar bascule automatiquement
   sur le repli suivant.
2. **`icon`** — nom d'icône **ou** rendu explicite (`{ src: '/logo.svg' }`, `{ component }`).
   L'icône occupe ~55% du disque.
3. **`name`** — les **initiales** (deux premiers mots, en majuscules).
4. Le **slot par défaut** — échappatoire (ex. l'agrégat « +X » de `VAvatarGroup`), remplace les
   initiales.

## Couleur automatique

À défaut d'image ou de couleur custom, une **teinte OKLCH déterministe** est dérivée du `name`
(hash pur JS, donc SSR-safe) : chaque personne obtient une couleur stable et distincte. Seule
la teinte est posée en ligne (`--avatar-hue`, scalaire) ; le CSS compose fond et texte avec des
clartés/chromas fixés **par thème**, donc l'adaptation clair/sombre se fait sans dépendre de
`contrast-color()`.

<Canvas of={VAvatarStories.CouleurAuto} />

> Comme pour la couleur custom de `VChip`/`VBadge`, la teinte auto est une couleur **calculée
> hors tokens** — exception assumée à la règle « aucune valeur brute », circonscrite au cas des
> avatars.

## Couleur custom

La prop `color` (hexadécimal, nom CSS ou `oklch()`) **remplace la teinte auto**, avec un texte
blanc fixe (le contraste d'une couleur claire est à la charge du consommateur).

<Canvas of={VAvatarStories.CouleurCustom} />

## Cliquable

Par priorité : `href` → `<a>`, sinon `clickable` → `<button>`, sinon `<span>` statique. Un lien
`disabled` devient **inerte** (href retiré + `aria-disabled`, modèle `VButton`). Seul l'avatar
interactif expose un survol et un anneau de focus clavier.

<Canvas of={VAvatarStories.Cliquable} />

## VTooltip

L'avatar ne porte aucune API de tooltip dédiée : on l'enveloppe dans un `VTooltip` et on lui
transmet `triggerProps` par fallthrough. Le tooltip s'ouvrant au survol **et au focus**,
l'avatar doit être focusable — le rendre `clickable` (bouton).

<Canvas of={VAvatarStories.AvecTooltip} />

## Accessibilité

- **Repli avec nom, non interactif** : l'avatar porte `role="img"` + `aria-label` (le `alt`
  prime sur le `name`). Les initiales/icône visibles sont `aria-hidden`.
- **Sans nom ni image** : décoratif — aucun rôle annoncé à tort.
- **Image** : le texte alternatif est porté par l'`alt` de l'`<img>` (`alt` ou `name`).
- **Interactif** (`<a>`/`<button>`) : le nom accessible vient de l'`aria-label` ; pas de
  `role="img"` superflu.
