# Input

Champ de saisie complet — label, icônes internes (cliquables), compteur, limite souple,
loading, effacement — construit autour d'un `<input>` natif stylé. La racine est un wrapper
(label + champ + hint) : les attributs natifs (`type`, `placeholder`, `required`,
`pattern`…) passent en fallthrough sur l'`<input>`, **sauf** `class`/`style` qui restent sur
la racine (les consommateurs dimensionnent le composant entier).

La validation reste native : `:user-invalid` fait le style d'erreur sans JavaScript de
validation.

## Tailles

Trois tailles (`sm` 32px, `md` 40px — défaut —, `lg` 48px, via les tokens
`--ds-control-height-*`). Les icônes internes suivent automatiquement (sm/md → 20px,
lg → 24px via le contexte `--ds-icon-size`). Les extrêmes de l'échelle du DS (`xs`, `xl`)
ne sont pas exposées : elles sont hors gabarit pour un champ de saisie.

<Canvas of={InputStories.Tailles} />

`compact` réduit la hauteur de 4px **sans toucher** au padding, à la typographie ni à la
taille des icônes (comme `Button`).

<Canvas of={InputStories.Compact} />

## Label et hint

`label` est associé au champ via `for`/`id` (`useId()`, SSR-safe) ; `hint` est lié via
`aria-describedby`. Sans `label`, fournir un nom accessible en fallthrough (`aria-label`).

<Canvas of={InputStories.LabelEtHint} />

## Icônes

`icon-start` / `icon-end` prennent un nom Material Symbols (les slots `#start` / `#end`
priment pour du contenu custom). Par défaut les icônes sont **décoratives** (`aria-hidden`) :

<Canvas of={InputStories.Icones} />

Attacher un listener `@click:icon-start` / `@click:icon-end` transforme l'icône en vrai
`<button>` — fournir alors son nom accessible via `icon-start-label` / `icon-end-label` :

<Canvas of={InputStories.IconesCliquables} />

## Compteur et limites

`counter` affiche « 12/80 » (ou « 12 » sans `maxlength`) à droite dans le champ. Par défaut,
`maxlength` est l'attribut natif : la saisie est **bloquée** à la limite.

<Canvas of={InputStories.Compteur} />

`soft-limit` rend la limite souple : la saisie peut dépasser, le champ passe en erreur via la
validation native (`setCustomValidity` → `:user-invalid` après interaction) et la soumission
est bloquée — jamais d'événement maison, la validité est exposée par l'API standard
(`el.validity`).

<Canvas of={InputStories.CompteurSoft} />

## Validation native

`pattern`, `required`, `type="email"`… restent les attributs natifs en fallthrough — zéro
JavaScript. Le style d'erreur (bordure rouge) vient de `:user-invalid` : il n'apparaît
qu'après interaction, comme le comportement natif.

La prop `invalid` force l'état d'erreur (validation serveur) — elle pose `aria-invalid` :

## États

`loading` affiche un spinner qui **remplace** l'emplacement de fin (`icon-end` / slot
`#end`) ; son libellé (`loading-label`) est annoncé via `role="status"` :

<Canvas of={InputStories.Loading} />

`clearable` affiche une croix quand le champ est non-vide (hors disabled/readonly) : elle
vide le champ, émet `clear` et **rend le focus** au champ :

<Canvas of={InputStories.Clearable} />

`readonly` : champ focusable et soumis mais non modifiable, fond légèrement enfoncé, bouton
d'effacement masqué :

<Canvas of={InputStories.Readonly} />

`disabled` bascule tout le champ (fond, texte, icônes) sur des nuances de gris
(`--ds-color-surface-muted`, `--ds-color-text-subtle`) — pas de jeu d'opacité, et le rendu
suit automatiquement le thème dark :

<Canvas of={InputStories.Disabled} />

## Accessibilité

- Toujours un nom accessible : `label`, ou `aria-label` en fallthrough à défaut.
- `hint` lié via `aria-describedby` (cumulable avec un `aria-describedby` fourni).
- Icônes décoratives (`aria-hidden`) ; icône cliquable → `<button>` avec
  `icon-*-label` obligatoire (un avertissement est émis en dev sans libellé).
- Focus visible : la bordure passe à 2px visuels (bordure + `box-shadow` même couleur) via
  `:focus-within`, rouge si invalide ; filet `outline` transparent pour le mode
  forced-colors.
- Erreur stylée par `:user-invalid` (après interaction) ; `invalid` pose `aria-invalid`.
