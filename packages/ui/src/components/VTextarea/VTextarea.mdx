# Textarea

Zone de texte complète — label, icônes internes (cliquables), compteur, limite souple,
loading, effacement — construite autour d'un `<textarea>` natif stylé. Miroir de `VInput` avec
deux différences : la prop `auto-grow` (hauteur qui suit le contenu, pur CSS) et le compteur
rendu **sous** le champ (sur la ligne du hint), jamais dedans.

Pas de prop `pattern` : `<textarea>` ne le supporte pas nativement et le composant ne
l'émule pas (décision projet). La racine est un wrapper : les attributs natifs passent en
fallthrough sur le `<textarea>`, sauf `class`/`style` qui restent sur la racine.

## Auto-grow

`auto-grow` fait suivre la hauteur au contenu via `field-sizing: content` — aucun JavaScript
de mesure. Sans support navigateur, le champ reste un textarea classique (progressive
enhancement). Le redimensionnement manuel (`resize`) est porté par le wrapper du champ, pas
par le `<textarea>`.

<Canvas of={VTextareaStories.AutoGrow} />

## Tailles

Trois tailles (`sm` 32px, `md` 40px — défaut —, `lg` 48px) qui jouent sur la typographie, le
padding et la hauteur minimale ; les icônes internes suivent (sm/md → 20px, lg → 24px via le
contexte `--vectis-icon-size`) et restent **alignées sur la première ligne** de texte. Comme pour
`VInput`, les extrêmes de l'échelle du DS (`xs`, `xl`) ne sont pas exposées.

<Canvas of={VTextareaStories.Tailles} />

`compact` réduit la hauteur minimale de 4px sans toucher au padding ni à la typographie.

<Canvas of={VTextareaStories.Compact} />

## Label, hint et compteur

`label` est associé via `for`/`id`, `hint` via `aria-describedby`. Le compteur (`counter`)
s'affiche sous le champ, à droite, sur la même ligne que le hint.

<Canvas of={VTextareaStories.LabelHintCompteur} />

`soft-limit` rend `maxlength` souple : la saisie peut dépasser, le champ passe en erreur via
la validation native (`setCustomValidity` → `:user-invalid` après interaction) et la
soumission est bloquée — la validité est exposée par l'API standard (`el.validity`).

<Canvas of={VTextareaStories.CompteurSoft} />

## Accessibilité

- Toujours un nom accessible : `label`, ou `aria-label` en fallthrough à défaut.
- `hint` lié via `aria-describedby` (cumulable avec un `aria-describedby` fourni).
- Icônes décoratives (`aria-hidden`) ; icône cliquable → `<button>` avec
  `icon-*-label` obligatoire (un avertissement est émis en dev sans libellé).
- Focus visible : la bordure passe à 2px visuels (bordure + `box-shadow` même couleur) via
  `:focus-within`, rouge si invalide ; filet `outline` transparent pour le mode
  forced-colors.
- Erreur stylée par `:user-invalid` (après interaction) ; `invalid` pose `aria-invalid`.

Les libellés accessibles de ce composant viennent du dictionnaire du design system : ils se traduisent globalement (voir **Fondations › Internationalisation**), et les props texte restent prioritaires pour un ajustement au cas par cas.
