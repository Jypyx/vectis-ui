# Textarea

Complete text area — label, internal (clickable) icons, counter, soft limit, loading, clearing —
built around a styled native `<textarea>`. A mirror of `VInput` with two differences: the
`auto-grow` prop (height following the content, pure CSS) and the counter rendered **under** the
field (on the hint's line), never inside it.

There is no `pattern` prop: `<textarea>` does not support it natively and the component does not
emulate it (a project decision). The root is a wrapper: the native attributes pass through by
fallthrough onto the `<textarea>`, except `class`/`style`, which stay on the root.

## Auto-grow

`auto-grow` makes the height follow the content through `field-sizing: content` — no measurement
JavaScript. Without browser support, the field stays a classic textarea (progressive
enhancement). Manual resizing (`resize`) is carried by the field's wrapper, not by the
`<textarea>`.

<Canvas of={VTextareaStories.AutoGrow} />

## Sizes

Three sizes (`sm` 32px, `md` 40px — the default —, `lg` 48px) acting on the typography, the
padding and the minimum height; the internal icons follow (sm/md → 20px, lg → 24px through the
`--vectis-icon-size` context) and stay **aligned on the first line** of text. As with `VInput`,
the extremes of the DS scale (`xs`, `xl`) are not exposed.

<Canvas of={VTextareaStories.Sizes} />

`compact` reduces the minimum height by 4px without touching the padding or the typography.

<Canvas of={VTextareaStories.Compact} />

## Label, hint and counter

`label` is associated through `for`/`id`, `hint` through `aria-describedby`. The counter
(`counter`) appears under the field, on the right, on the same line as the hint.

<Canvas of={VTextareaStories.LabelHintCounter} />

`soft-limit` makes `maxlength` soft: input may go over, the field enters error through native
validation (`setCustomValidity` → `:user-invalid` after interaction) and submission is blocked —
the validity is exposed by the standard API (`el.validity`).

<Canvas of={VTextareaStories.SoftCounter} />

## States

`loading` shows a spinner that **replaces** the end slot (`icon-end` / `#end`); its label
(`loading-label`) is announced through `role="status"`:

<Canvas of={VTextareaStories.Loading} />

`clearable` shows a cross when the field is non-empty (outside disabled/readonly): it empties the
field, emits `clear` and returns focus to the field:

<Canvas of={VTextareaStories.Clearable} />

`readonly`: a field that is focusable and submitted but not editable, with a slightly sunken
background and the clear button hidden:

<Canvas of={VTextareaStories.Readonly} />

`disabled` switches the whole field to greys — no opacity trick, and the rendering is dark-theme
compatible:

<Canvas of={VTextareaStories.Disabled} />

The `invalid` prop forces the error state (server-side validation) — it sets `aria-invalid`:

<Canvas of={VTextareaStories.Invalid} />

It composes with `readonly` — the sunken background and the red border are two independent
decisions, and an error stays visible on a field whose value is set elsewhere. On a read-only
field the error can only come from the `invalid` prop: a read-only control is barred from
constraint validation, so `:user-invalid` never applies to it.

## Accessibility

- Always an accessible name: `label`, or `aria-label` by fallthrough failing that.
- `hint` linked through `aria-describedby` (which stacks with a supplied `aria-describedby`).
- Decorative icons (`aria-hidden`); a clickable icon → a `<button>` with a mandatory
  `icon-*-label` (a warning is emitted in dev when the label is missing).
- Visible focus: the border goes to a visual 2px (border + a `box-shadow` of the same colour)
  through `:focus-within`, red when invalid; a transparent `outline` rule for forced-colors mode.
- Errors styled by `:user-invalid` (after interaction); `invalid` sets `aria-invalid`.

This component's accessible labels come from the design system's dictionary: they translate
globally (see **Foundations › Internationalization**), and the text props stay authoritative for
a case-by-case adjustment.
