# InputOTP

Code à usage unique (OTP) — une case par caractère, construites sur des `<input>` natifs.
Il n'existe pas de primitive HTML « code à N caractères » : le JavaScript orchestre le
clavier et le collage (avance automatique, retour arrière, distribution sur les cases,
flèches). `autocomplete="one-time-code"` sur la première case : le remplissage automatique
(SMS, gestionnaire de mots de passe) est distribué sur l'ensemble.

Le v-model est la concaténation des caractères saisis ; `complete` est émis quand toutes
les cases sont remplies.

## Collage

Coller un code dans n'importe quelle case le distribue à partir de celle-ci — un seul
handler `input` couvre saisie et collage, aucun événement `paste` dédié :

## Tailles

Trois tailles (`sm` 32px, `md` 40px — défaut —, `lg` 48px, via les tokens
`--vectis-control-height-*`) ; comme pour `VInput`, les extrêmes de l'échelle du DS (`xs`, `xl`)
ne sont pas exposées.
Les cases sont carrées : la largeur suit la hauteur, la typographie et les icônes de
séparateur s'ajustent avec. `compact` réduit la hauteur (et donc la largeur) de 4px sans
toucher à la typographie (comme `VButton`/`VInput`) :

<Canvas of={VInputOTPStories.Tailles} />

## Format

`format` définit le jeu de caractères accepté : `numeric` (défaut, chiffres seuls,
clavier numérique via `inputmode`), `alpha` (lettres) ou `alphanumeric`. Hors `numeric`,
les minuscules sont converties en majuscules à la saisie : le v-model est canonique, la
comparaison serveur ne dépend pas de la casse.

<Canvas of={VInputOTPStories.FormatAlphanumerique} />

## Pattern

`pattern` décrit un gabarit : chaque `#` devient une case, tout autre caractère un
littéral décoratif (typo mono, couleur atténuée, `aria-hidden`). Les littéraux ne font
**pas** partie du v-model — pour `###.###.###` rempli, le modèle vaut `123456789`. Le
nombre de cases dérive du pattern, qui prime sur `length`.

Le collage est « pattern-aware » : coller la chaîne formatée (`123.456.789`) fonctionne,
les littéraux collés sont consommés positionnellement, le reste est filtré par `format` :

<Canvas of={VInputOTPStories.AvecPattern} />

Un préfixe textuel (`GT-###`) est rendu comme littéraux ; coller `GT-123` ne garde que
`123` :

<Canvas of={VInputOTPStories.PatternPrefixe} />

## Séparateur en icône

`separator-icon` (nom d'icône ou rendu explicite) remplace **tous** les littéraux du pattern par une
icône — réservé aux gabarits purement séparateurs (`####-####`), ne pas le combiner avec
un préfixe textuel. L'icône suit la taille du composant via le contexte `--vectis-icon-size`
et hérite sa couleur (currentcolor) :

<Canvas of={VInputOTPStories.SeparateurIcone} />

## États

La prop `invalid` force l'état d'erreur (validation serveur) — bordures rouges et
`aria-invalid` sur chaque case :

(`--vectis-color-surface-muted`, `--vectis-color-text-subtle`) — pas de jeu d'opacité, et le rendu

## Accessibilité

- La racine est un `role="group"` nommé par `label` (« Code de vérification » par défaut).
- Chaque case porte un `aria-label` « Caractère N sur M » compté sur les cases éditables —
  les littéraux du pattern sont décoratifs (`aria-hidden`) et jamais focusables.
- Navigation clavier : flèches gauche/droite entre cases, Backspace sur case vide efface
  la précédente et y retourne — les littéraux sont traversés de façon transparente.
- Focus visible : bordure 2px visuels (bordure + `box-shadow` même couleur, alignée sur
  `VInput`), rouge si invalide ; filet `outline` transparent pour le mode forced-colors.
- Les transitions respectent `prefers-reduced-motion`.

Les libellés accessibles de ce composant viennent du dictionnaire du design system : ils se traduisent globalement (voir **Fondations › Internationalisation**), et les props texte restent prioritaires pour un ajustement au cas par cas.
