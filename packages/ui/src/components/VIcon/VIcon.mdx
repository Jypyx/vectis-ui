# Icon

Icon with four sources, resolved in a fixed order: image (`src`), then `name` — the consumer's
resolver first, then the drawing the icon **brought along with it**, otherwise the **ligature**
of the consumer's font — otherwise the **inline SVG** passed in the slot.

> The icons the library renders itself (crosses, chevrons, the toast tone icons…) are
> **embedded** SVGs, exact replicas of
> [Material Symbols Rounded](https://fonts.google.com/icons) (wght 400 · GRAD 0 · opsz 24).
> **The design system therefore requires no icon font.** The font stays useful for your own
> icon names; it is loaded by the consuming application (see the README).

Each of them is a **module of its own**, imported from `vectis-ui/icons` and passed where a
name would go — so a consumer pays for the icons their components actually draw and for
nothing else. A lone `VButton` ships none at all.

```ts
import { close } from 'vectis-ui/icons'
```

```vue
<VIcon :name="close" />
```

A **bare string stays a NAME**: it goes to your resolver and then to the icon font, and it no
longer reaches the library's own drawings. That is the deliberate half of the arrangement — an
icon reaches a bundle because a module imported it, never because a string might one day ask
for it.

## Size

**1em by default**: the icon follows the size of the surrounding text, with no configuration.
The `size` prop (a number, in pixels) allows a free override: `:size="32"` → 32px.

<Canvas of={VIconStories.TextAdapted} />

## Four sources

`src` wins over `name`, which wins over the slot. An icon imported from `vectis-ui/icons`
gives an SVG; a bare name falls back to the ligature, hence to the consumer's font. The image gets an
empty `alt` (the accessible name comes from `label`, never from the source); the inline SVG
fills the icon's square.

<Canvas of={VIconStories.FourSources} />

The **`data-icon`** attribute carries the requested name whatever the effective source — a
stable hook for consumer CSS (`.v-icon[data-icon='close'] { … }`) as well as for tests.

## Driven by the parent

Without a `size` prop, any parent can size its icons by setting the custom properties
**`--vectis-icon-size`** (size) and **`--vectis-icon-opsz`** (optical axis). That is what
`VButton`, `VInput` and `VTextarea` do according to their own size (sm → 16px/opsz 20,
md → 20px/opsz 20, lg → 24px/opsz 24). Resolution follows the priority: numeric `size` prop >
parent context > 1em.

**`--vectis-icon-opsz` only applies to the ligature**: it is a variable font axis, with no
purchase on an embedded SVG (drawn at opsz 24), an image or an inline SVG. The size, on the
other hand, applies to every source.

## Fill

The `filled` prop asks for the filled variant (the Material Symbols **`FILL`** axis, 0 = outline
→ 1 = filled). It is honoured by the **ligature** and by the **built-in registry**, which embeds
a second path for the icons whose geometry really changes (`check_circle`, `warning`, `info`…) —
the purely linear icons (`close`, chevrons, arrows) are identical in both states. No effect on
an image (`src`) or an inline SVG.

## Wiring in an icon library

`setIconResolver` is consulted **before** the icon's own drawing: that is what lets you move all
of the DS's icons onto your own source with a single call. An imported icon carries its **name**
as well as its paths, which is exactly what keeps it reaching you — a bare `{ path }` would take
the `render` route and never be offered. Returning `undefined` means "I do not know this name"
and hands over to that drawing, then to the ligature — so **partial** mappings are usable.

Set it at **module** level (a Nuxt plugin, `main.ts`), never inside a `setup()`, and never
client-only: the server would render the embedded SVG and the client your library.

The stories below all render **the same showcase** — VButton, VInput, VChip, VBreadcrumb,
VAccordion, VPagination, plus the full grid of built-in icons. Only the resolver changes. The
fonts are loaded by `.storybook/preview-head.html` from a CDN: none of them is a dependency of
the package.

### Class fonts

Font Awesome, Phosphor, Bootstrap Icons… — the glyph comes from a `::before` carried by
classes. `classIconResolver` covers them all; VIcon then renders a
`<span class="v-icon-glyph …">` that belongs to it, and which it therefore normalizes in a
single rule.

The `strict` parameter (the default) protects the DS's icons: one of its names **absent** from
your alias table would fall onto a non-existent class — hence an empty square — so it falls back
to the embedded SVG instead. It is a **set of names** the resolver consults for that, never the
drawings, so wiring in your own library downloads none of the Material paths. Your own names always pass: they are already written in your
library's vocabulary.

### SVG sets as components

Lucide, Untitled UI… — `componentIconResolver` renders the component as-is. Contract: a
**single `<svg>` root**, since that is what the CSS sizes, even against a hardcoded
`width`/`height` (Lucide writes `width="24"`: a presentation attribute, beaten by any author
rule).

<Canvas of={VIconStories.ComponentSet} />

### Ligature fonts

Material Symbols (every variant) and the ligature IcoMoon builds. `ligatureIconResolver()` sends
the DS's icons back to the font **as well**: this is how to get back the optical axis
`--vectis-icon-opsz`, which the registry — drawn at opsz 24 — cannot reproduce. To change only
the variant (Outlined, Sharp), overriding the `--vectis-font-family-icon` token is enough, with
no resolver.

<Canvas of={VIconStories.LigatureFont} />

### With no resolver at all

The DS's icons show up (built-in registry); **your** names land on the ligature branch, hence on
`--vectis-font-family-icon`. With a class font loaded but no resolver, they appear as fragments
of words clipped to the icon's square — visible and local, never a broken layout, and never
announced (the icon is `aria-hidden`). Otherwise, every prop also accepts a one-off explicit
render: `:icon-start="{ class: 'ph ph-house' }"`.

## Accessibility

The icon is **decorative by default** (`aria-hidden="true"`): inside a button or a field, the
accessible name comes from the label, not from the icon. The `label` prop makes it informative:
`role="img"` + `aria-label`, with no `aria-hidden`.
