# Icon

Icône à quatre sources, résolues dans un ordre fixe : image (`src`), puis `name` — d'abord le
**registre intégré**, sinon la **ligature** de la police du consommateur — sinon le **SVG
inline** passé en slot.

> Les icônes que la librairie rend elle-même (croix, chevrons, icônes de tone des toasts…)
> sont des SVG **embarqués**, répliques exactes de
> [Material Symbols Rounded](https://fonts.google.com/icons) (wght 400 · GRAD 0 · opsz 24).
> **Le design system ne requiert donc aucune police d'icônes.** La police reste utile pour vos
> propres noms d'icônes ; elle est chargée par l'application consommatrice (voir le README).

## Taille

**1em par défaut** : l'icône suit la taille du texte environnant, sans configuration. La prop
`size` (nombre, en pixels) permet une surcharge libre : `:size="32"` → 32px.

<Canvas of={IconStories.AdapteeAuTexte} />

## Quatre sources

`src` prime sur `name`, qui prime sur le slot. Un `name` du registre intégré donne un SVG ;
tout autre nom retombe sur la ligature, donc sur la police du consommateur. L'image reçoit un
`alt` vide (le nom accessible vient de `label`, jamais de la source) ; le SVG inline remplit le
carré de l'icône.

<Canvas of={IconStories.QuatreSources} />

L'attribut **`data-icon`** porte le nom demandé quelle que soit la source effective — accroche
stable pour du CSS consommateur (`.v-icon[data-icon='close'] { … }`) comme pour les tests.

## Pilotage par le parent

Sans prop `size`, tout parent peut dimensionner ses icônes en posant les custom properties
**`--vectis-icon-size`** (taille) et **`--vectis-icon-opsz`** (axe optique). C'est ce que font `Button`,
`Input` et `Textarea` selon leur propre taille (sm → 16px/opsz 20, md → 20px/opsz 20,
lg → 24px/opsz 24). La résolution suit la priorité : prop `size` numérique > contexte
parent > 1em.

**`--vectis-icon-opsz` ne s'applique qu'à la ligature** : c'est un axe variable de police, sans
prise sur un SVG intégré (dessiné à opsz 24), une image ou un SVG inline. La taille, elle, vaut
pour toutes les sources.

<Canvas of={IconStories.PiloteParLeParent} />

## Remplissage

La prop `filled` demande la variante pleine (axe **`FILL`** de Material Symbols, 0 = contour →
1 = plein). Elle est honorée par la **ligature** et par le **registre intégré**, qui embarque un
second path pour les icônes dont la géométrie change réellement (`check_circle`, `warning`,
`info`…) — les icônes purement linéaires (`close`, chevrons, flèches) sont identiques dans les
deux états. Sans effet sur une image (`src`) ou un SVG inline.

## Brancher une bibliothèque d'icônes

`setIconResolver` est consulté **avant** le registre intégré : c'est ce qui permet de faire
passer toutes les icônes du DS sur votre propre source. Rendre `undefined` signifie « je ne
connais pas ce nom » et laisse la main au registre, puis à la ligature — les mappings
**partiels** sont donc utilisables.

À poser au niveau **module** (plugin Nuxt, `main.ts`), jamais dans un `setup()`, et jamais en
client-only : le serveur rendrait le SVG intégré et le client votre bibliothèque.

Les stories ci-dessous rendent toutes **la même vitrine** — Button, Input, Chip, Breadcrumb,
Accordion, Pagination, plus la grille complète des icônes intégrées. Seul le résolveur change.
Les polices sont chargées par `.storybook/preview-head.html` depuis un CDN : aucune n'est une
dépendance du package.

### Polices à classes

Font Awesome, Phosphor, Bootstrap Icons… — le glyphe vient d'un `::before` porté par des
classes. `classIconResolver` les couvre toutes ; Icon rend alors un
`<span class="v-icon-glyph …">` qui lui appartient, donc qu'il normalise d'une seule règle.

<Canvas of={IconStories.PoliceFontAwesome} />

Le paramètre `strict` (défaut) protège les icônes du DS : un nom du registre **absent** de
votre table d'alias retomberait sur une classe inexistante — donc un carré vide — alors il
retombe sur le SVG intégré. Vos propres noms, eux, passent toujours : ils sont déjà écrits
dans le vocabulaire de votre bibliothèque.

<Canvas of={IconStories.MappingPartiel} />

### Jeux SVG en composants

Lucide, Untitled UI… — `componentIconResolver` rend le composant tel quel. Contrat : **racine
`<svg>` unique**, c'est elle que le CSS dimensionne, y compris contre un `width`/`height` en
dur (Lucide écrit `width="24"` : un attribut de présentation, battu par toute règle d'auteur).

<Canvas of={IconStories.JeuDeComposants} />

### Polices à ligatures

Material Symbols (toutes variantes) et les builds IcoMoon à ligatures. `ligatureIconResolver()`
renvoie **aussi** les icônes du DS vers la police : c'est la façon de retrouver l'axe optique
`--vectis-icon-opsz`, que le registre — dessiné à opsz 24 — ne peut pas reproduire. Pour changer
seulement de variante (Outlined, Sharp), surcharger le token `--vectis-font-family-icon` suffit,
sans résolveur.

<Canvas of={IconStories.PoliceLigature} />

### Sans résolveur du tout

Les icônes du DS s'affichent (registre intégré) ; **vos** noms tombent sur la branche ligature,
donc sur `--vectis-font-family-icon`. Avec une police à classes chargée mais aucun résolveur, ils
apparaissent en fragments de mots rognés au carré de l'icône — visible et local, jamais une
mise en page cassée, et jamais annoncé (l'icône est `aria-hidden`). Sinon, chaque prop accepte
aussi un rendu explicite ponctuel : `:icon-start="{ class: 'ph ph-house' }"`.

## Accessibilité

L'icône est **décorative par défaut** (`aria-hidden="true"`) : dans un bouton ou un champ,
le nom accessible vient du libellé, pas de l'icône. La prop `label` la rend informative :
`role="img"` + `aria-label`, sans `aria-hidden`.
