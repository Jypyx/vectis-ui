# DataTable

A data table in strictly semantic HTML (`<table>`, `caption`, `scope`, `aria-sort`), composed of
the design system's bricks: `VInput` for the search, `VCheckbox` for the selection, `VMenu` +
`VButton` for the rows per page, `VPagination` for the footer. The whole local machinery (filtering
→ sorting → pagination) is a chain of pure derivations; a server mode short-circuits it entirely.

## Sorting

A `sortable` column renders its header as a button: clicking cycles **ascending → descending →
none**, the state lives in `v-model:sort` (the exported `DataTableSort` type) and the `<th>` carries
`aria-sort`. Sorting does not reset the current page: you sort what you are looking at.

The indicator follows those three states: a neutral, dimmed glyph signals the affordance on sortable
columns, replaced on the active column by the direction's arrow — pointing down when ascending, up
when descending, following the spreadsheet convention. Purely decorative: `aria-sort` is what
carries the information for assistive technologies.

The three glyphs are replaced independently through `sortIcon` (sortable but unsorted), `sortAscIcon`
and `sortDescIcon` — an icon name or an explicit render, as everywhere in the design system.
Overriding only one leaves the other two at their default.

## Header and search

`title` (or the `#header` slot, which wins) fills the left zone of the global header; `searchable`
displays a clearable search-type `VInput` on the right, bound to `v-model:search`. The local filter
is case- and accent-insensitive and only walks the **declared columns** — never the rows' other
fields. A change of term returns to page 1.

<Canvas of={VDataTableStories.Search} />

## Pagination

Local pagination activates as soon as `perPage` is defined (`v-model:per-page`, or a one-way
`:per-page`): the footer appears. Its right zone groups, in this order, the rows-per-page selector
(`perPageOptions`, a `VMenu` of selected items), the "X–Y of Z" text (`showRange`, formattable
through `rangeLabel`) and the design system's `VPagination` driven by `v-model:page`; the left zone
stays empty outside selection. If a filter reduces the number of pages, the display falls back to
the last page by **derivation**, without mutating the model.

<Canvas of={VDataTableStories.LocalPagination} />

## Selection

`selectable` adds a `VCheckbox` column at the far left and a "master" box in the `<thead>`: checked
when the whole **visible page** is selected, indeterminate when it is partially, it never touches
the selections of other pages (the Material model). `v-model:selected` receives the row identities
(`DataTableRowId[]`), derived from `rowKey` — required in practice: without it, index-based
identities are corrupted by sorting and pagination (with a development warning). The count appears
on the left of the footer (`selectionLabel` to rephrase it), in a live region announced on every
change: it is set as soon as `selectable` is — empty while nothing is selected — and makes the
footer appear even with no pagination.

<Canvas of={VDataTableStories.Selection} />

## Server mode

`serverSide` disables **all** local processing: the rows received are displayed as they come (they
represent the current page) and every change of page, sort, rows per page or search emits
`update:params` (the exported `DataTableParams` type: `page`, `perPage`, `sortKey`, `sortDirection`,
`search`). The search is debounced (`searchDebounce`, 250 ms by default, `0` = synchronous) and its
commit returns to page 1 within the **same** emission. Supply `total` (the number of rows on the
server) for the page and range computation. Nothing is emitted on mount: the initial fetch belongs
to the consumer.

## Decoration

`variant` drives the table's frame, on the scale shared with `VAccordion` and `VTabs`. `flat` (the
default) adds nothing: the table sits bare, its header, rules and footer flush with the host
container. `outlined` encloses it in a surface of its own, rounded and ringed by a rule; the title
bar, the caption and the footer then take the frame's gutter, aligned on the cells' padding — their
content lines up exactly with the first column's text and follows `compact`. Only the table keeps
scrolling edge to edge.

<Canvas of={VDataTableStories.Variants} />

## Appearance

`striped` alternates the background of even rows; `compact` reduces the cell paddings by one notch
and switches the composed parts (the search, the footer) to compact; `stickyHeader` freezes the
header row on vertical scrolling — it assumes a bounded scroll area, through `height` or through a
parent with a defined height (see **Height**), otherwise nothing scrolls under the header. Its
opaque background takes the variant's surface: no seam at the frame's edge, dark theme included.

## Height

The table takes **100% of its parent's height** as soon as the parent has one: its height then stops
depending on the number of rows rendered, and an incomplete last page no longer makes it contract —
the pagination stays stuck to the bottom and only the table scrolls. No prop, no measuring JS: the
root is a flex column of height `100%`, a percentage that falls back to `auto` when the parent sizes
itself to its content. Existing tables are therefore unchanged as long as their host is not bounded.

`height` (a number → px, or any CSS length) bounds the **whole component**, the title bar and the
pagination included. For a plain ceiling, set `style="max-block-size: …"`; inside a flex column
parent, prefer `style="flex: 1; min-block-size: 0"` to a hardcoded height.

The free space left under the last rows stays bare: the striping does not extend onto rows that do
not exist — since rows have no fixed height, a background pattern would shift as soon as a cell
wrapped onto two lines.

<Canvas of={VDataTableStories.FullHeight} />

## Responsive

`responsive="scroll"` (the default) scrolls the table horizontally — the header and the footer stay
put, only the table moves. `responsive="stack"` turns each row into a card under 640px of
**container** (a container query, no measuring JS): the headers are re-injected in front of each
cell through `data-label`, and the selection box opens the card.

<Canvas of={VDataTableStories.ResponsiveStack} />

## Slots

- `#header`: the left zone of the global header (wins over `title`).
- `#head-<key>` (scope: `{ column }`): the label of a column header — rendered **inside** the sort
  button when the column is sortable, so place only non-interactive content there.
- `#cell-<key>` (scope: `{ row, value, column }`): the content of a cell.

## Accessibility

- A native table: `caption` (a dedicated prop), `scope="col"` on the headers, `aria-sort` set on the
  sorted `<th>`; the sort trigger is a real `<button>`.
- The attributes passed through fallthrough (`aria-describedby`, `id`…) land on the `<table>`;
  `class` and `style` stay on the root.
- A selected row: a `data-selected` marker and **not** `aria-selected` — that attribute is invalid on
  a `row` of `role="table"` (it is reserved for grids); the accessible state is carried by the
  checked box. The boxes get their name through `selectAllLabel` and `selectRowLabel`.
- The "X–Y of Z" text is in `aria-live="polite"`: page changes are announced.
- Every default label comes from the design system dictionary and is overridable through props
  (`searchLabel`, `perPageLabel`, `selectAllLabel`…).
- The `title` prop shadows the global HTML attribute of the same name on the component: to set a
  native tooltip, target an inner element.

This component's accessible labels come from the design system dictionary: they translate globally
(see **Foundations › Internationalization**), and the text props stay authoritative for a
case-by-case adjustment.
