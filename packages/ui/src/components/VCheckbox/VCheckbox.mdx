# Checkbox

Checkbox built on the native `<input type="checkbox">`, visually replaced by a styled box: the
input stays in the tree (focus, keyboard, forms, `:user-invalid`), and only its rendering is
hidden. The input sits inside a `<label>`, so clicking the label ticks the box with no
`for`/`id`; the root is a layout box around that label and the optional hint. The JavaScript
beyond the v-model bridge is `indeterminate`, which exists solely as a DOM property, and the
refusal `readonly` asks for.

A single size: a 20px box with a 2px border (the `--vectis-control-size-check` and
`--vectis-control-border-width` tokens), and a 14px tick (`--vectis-control-size-check-mark`).

## Label position

`label-position` places the label after (`end`, the default) or before (`start`) the box.

<Canvas of={VCheckboxStories.LabelPosition} />

## Label and hint

`label` is the text beside the box, and the default slot replaces it when the label needs
more than text. `hint` draws a caption underneath, tied to the input through
`aria-describedby`: a consumer's own `aria-describedby` is kept and the hint appended to it. The
hint is rendered outside the `<label>`, since everything inside a label becomes the accessible
name, and it lines up with the text on either side (`label-position`, `spread`).

<Canvas of={VCheckboxStories.WithHint} />

## Spread

`spread` makes the root take the full width: label and box are pushed to the container's
opposite ends. It combines with `label-position` to choose which side the box goes to.

<Canvas of={VCheckboxStories.Spread} />

## Indeterminate

`indeterminate` shows the "partially checked" visual state (a dash), typical of a "select all"
box above a list. It is a purely visual state: it does not change the v-model's value and exists
only as a DOM property (there is no equivalent HTML attribute).

## States

`disabled` switches the box to greys (`--vectis-color-surface-muted`,
`--vectis-color-text-subtle`) — no opacity trick, and the rendering follows the dark theme
automatically:

<Canvas of={VCheckboxStories.Disabled} />

## Read-only

`readonly` shows the state without letting it change. The native attribute has no effect on a
checkbox, so the component cancels the click, which also covers Space and a click on the label:
the browser puts `checked` and `indeterminate` back and fires no `change`. The box stays
focusable, is submitted with its form and carries `aria-readonly`. It sinks like a read-only
field (`--vectis-color-surface-sunken`), and a ticked box trades the accent for
`--vectis-color-text-muted`.

## Forms and validation

The native attributes (`name`, `value`, `required`, `aria-*`…) pass through by fallthrough onto
the input, not onto the wrapper, where only `class` and `style` stay: the box takes part in forms normally. The invalid state is styled
through `:user-invalid` (native validation, after interaction); the `invalid` prop allows forcing
it server-side — it sets `aria-invalid`.

## Accessibility

- The label (prop or slot) names the control, and the hint describes it: always supply a label, or an `aria-label`
  by fallthrough failing that.
- The input is hidden with `opacity: 0` (never `display: none`): it stays focusable by keyboard
  and submitted with the form.
- Visible focus through a ring (`--vectis-focus-ring-*`) on the box, never removed.
- `readonly` keeps the box in the tab order and sets `aria-readonly`.
- The transitions respect `prefers-reduced-motion`.
