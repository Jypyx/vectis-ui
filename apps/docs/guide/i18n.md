# Internationalization

No user-facing text is hardcoded in a component: everything comes from a dictionary. The
library is English by default and ships French; any other language is added on your side,
with the same gesture.

## Words and formats are settled separately

The **words** come from the dictionary. The **formats** — month and day names, date field
order, hour cycle, first day of the week — derive from `Intl` from the locale tag.

So setting a locale the library has no dictionary for already gives you correct dates,
with labels left in English. That is a coherent degraded state, not a bug.

## Switching to French

```ts
// main.ts
import { fr, registerMessages, setLocale } from '@vectis/ui'

registerMessages('fr', fr)
setLocale('fr-FR')
```

French is opt-in: it enters your bundle only if you import it. The argument is not weight
— it is about 0.8 kB gzipped — but uniqueness of mechanism: enabling the shipped French
and adding a language the library does not ship are the same call, rather than two
categories of dictionary.

Set a **complete** BCP 47 tag. `Intl` accepts `'en'`, but applies the language's default
conventions to it, and `'en'` means a 12-hour clock and a week starting on Sunday — which
is not `'en-GB'`.

## Adjusting a few words

An override is partial: what you do not write stays unchanged, and successive calls on the
same language accumulate.

```ts
import { registerMessages } from '@vectis/ui'

registerMessages('en', {
  dataTable: { empty: 'Nothing to display' },
  common: { close: 'Quit' },
})
```

## Adding a language

```ts
import { registerMessages, setLocale, type VectisMessagesInput } from '@vectis/ui'

const de: VectisMessagesInput = {
  common: { loading: 'Wird geladen…', close: 'Schließen' },
  pagination: { previous: 'Vorherige Seite', next: 'Nächste Seite', page: (p) => `Seite ${p}` },
}

registerMessages('de', de)
setLocale('de-DE')
```

What you do not write falls back to English, never to an empty string, so a partial
dictionary is usable from its very first key.

A message that depends on a value is a **TypeScript function**, not a placeholder string:
there is no plural engine and no ICU syntax to learn, and your editor checks the
signature. Type the constant as `VectisMessagesInput` for key completion, or as
`VectisMessages` to have the compiler demand full coverage.

The key is the language subtag alone: `registerMessages('de', …)` covers `de-DE`, `de-AT`
and `de-CH`.

## Precedence

A text prop set on a component stays authoritative — a global translation only changes
defaults. For a container's accessible name the full chain is:

```
aria-labelledby › aria-label › the label prop › the dictionary › English
```

`VCalendar`, `VDatePicker` and `VTimePicker` keep a `locale` prop, which takes precedence;
without it they follow the global locale.

```vue
<VDatePicker />
<!-- the global locale -->
<VDatePicker locale="ja-JP" />
<!-- forced -->
```

## Limit: one locale per process

The configuration lives at module level, like the icon resolver's. A server-rendered site
serving `/fr` and `/en` from the same Node process cannot use it to vary the language per
request — those pages have to pass the text props explicitly.

This is a real constraint, and this site lives with it: it is generated in one process, so
it is English only.
